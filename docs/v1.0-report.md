# v1.0 Work Report: .NET 10 and Backlog Items

**Date:** 2026-10-10
**Branch:** `v1.0` (from `phase-6-rc`)
**Environment:** Windows 11 Pro (10.0.26300), .NET SDK 10.0.401, runtime 10.0.12 (system-wide, next to SDK 9.0.301), Node.js 22.14.0

PRD §15 "Release and Later" puts v1.0 after Phase 6: all P0/P1 items done, AC-1 to AC-13 passing. This round did the .NET 10 move and five backlog items. The manual checks from Phases 4–6 are still open (see the end).

## What changed

| Item | Decision | Result |
|------|----------|--------|
| Move to .NET 10 LTS (.NET 8 support ends 2026-11-10) | D-63 | All projects `net10.0` / `net10.0-windows`, C# 14, `global.json` needs SDK 10.0.100+. Microsoft packages 10.0.12, H.NotifyIcon.Wpf 2.4.1. |
| Start with Windows (FR-31) | D-64, D-75 | Options > General checkbox, **on by default** for an installed copy; a portable copy and an upgrade from a version 1 settings file stay off. Per-user Run value, repaired after a folder move, never taken from another working copy. |
| Edge support | D-65 | Register/Unregister cover Chrome and Edge keys; same extension and ID. A Chrome-only registration is completed on start. |
| Expired signed URLs mid-download (§16.1) | D-66 | A 401/403/404/410 makes the job ask the original link for a fresh address (shared, max 3 per run). Same file: it continues. Same address or a different file: it fails as before. |
| Remember website sign-ins (§11.1) | D-67 | Opt-in. Cookies of unfinished downloads are DPAPI-encrypted (current user) in `download_secrets` (migration 003) and deleted on completion, removal, or when the option is turned off. |
| Smaller, faster host.exe | D-68 | Source-generated protocol JSON; host published trimmed + ReadyToRun. |
| IDM-style media button (FR-24) | D-69 | "Download with OB2" floats over videos with a direct file; "Download media with OB2" on video/audio context menus. New `webRequest` permission (observe only). HLS/DASH streams are not offered. Extension tests 68 → 103. |
| "Find downloads on this page" (link grabber) | D-70 | The popup lists the download links in the page and its frames, including addresses hidden in scripts; each has a Download button. New `scripting` permission. The video button falls back to media addresses in the page code. Extension tests 103 → 119. |
| YouTube and streaming sites with a quality and audio choice | D-71 | yt-dlp + ffmpeg + Deno, downloaded on first use (≈150 MB, checksums verified) through OB2's engine. New Download Video window; video pages are normal rows with pause/resume. Migration 004. .NET tests +30, extension tests 119 → 136. |

## Safety checks

The tests touch the registry only under `HKCU\Software\OB2.Tests\<guid>` and remove it. After the full run: no `com.ob2.host` key for Chrome or Edge, no `OB2` Run value, no scratch key left.

## Still open (owner)

Unchanged from the phase reports: Phase 4 UI checklist, 125/150 % DPI, and Flow C; Phase 5 clean-VM run (AC-8) and VirusTotal; Phase 6 real-browser clicks (AC-5/AC-6). Phase 6's checklist now applies to Edge as well. New items to try by hand:

1. Options > General > "Start OB2 in the tray when I sign in to Windows", then sign out and back in: OB2 is in the tray.
2. Options > General > "Remember website sign-ins…": start a download that needs a sign-in, exit OB2, start it again, Resume. It finishes.
3. Options > Browser > Register, then load the extension in Edge (`edge://extensions`) and click a download link.
4. Media button (D-69). Rebuild the extension, then click **Reload** on it in `chrome://extensions`. An unpacked extension takes the new `webRequest` permission on reload without a prompt.
   - Open a page with a plain `<video src="….mp4">` (or open an `.mp4` address directly). Hover the video: “Download with OB2” appears at its top right. Click it: OB2’s Add window opens with the file, named after the page when the address has no file name.
   - A player that uses a `blob:` source but loads a whole file (many news and social sites): the button shows a count and a menu of files with sizes.
   - An HLS/DASH site (most live streams, YouTube): no button, by design.
   - Right-click a video → “Download media with OB2”: the same file goes to OB2. Turn off “Show a download button on videos” in the popup: the button stops appearing.
   - Fullscreen a player (not the bare `<video>`): the button still appears on hover. Exit OB2 and click the button: OB2 starts and the Add window appears.
5. Link grabber (D-70). Reload the extension, refresh a page that has download links or a player whose address is in its source (Inspect shows it), open the popup and click **Find downloads on this page**. The links are listed (videos first); click **Download** on one: OB2's Add window opens with it, and the row says "Sent". A `.m3u8` row says "Stream: not supported yet". On `chrome://extensions` the popup explains it can't read that page.
6. YouTube (D-71). Exit OB2 and rebuild it, reload the extension, open a YouTube video and hover it: "Download with OB2". Click it: the Download Video window opens. The first time it offers **Download the tools** (about 150 MB; on a slow line this takes a while, and closing the window keeps what arrived). Then pick a quality (for example 1080p) and an audio track, or "Audio only", and **Download Now**: the row shows progress and speed; Pause and Resume work; the finished MP4 plays with sound. Also try a YouTube Short, a right-click on a YouTube link → "Download with OB2", and pasting a YouTube address into Add URL ("Choose quality…").
