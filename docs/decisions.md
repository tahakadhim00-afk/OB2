# Decisions

Choices made where the PRD says *(decide)*, leaves a detail open, or where the build deviates from §13. Newest last.

| # | Phase | Decision | Reason |
|---|-------|----------|--------|
| D-1 | 1 | The project has its own git repo at `OB2/`. | The enclosing folder sits inside an unrelated repo rooted at the user profile. Phase branches and tags must not mix with it. |
| D-2 | 1 | The PRD stays at the repo root as `OB2_PRD.md` rather than `docs/PRD.md` (§7.3). | That is the file the owner works from; a copy would drift. |
| D-3 | 1 | Target `net8.0` / `net8.0-windows` as §6.2 specifies. Built with the .NET 9 SDK (9.0.301); tests run on the .NET 8 runtime. | Follows §13. **Note:** .NET 8 support ends 2026-11-10. Moving to .NET 10 LTS is logged in the backlog for the owner to approve. |
| D-4 | 1 | FluentAssertions is pinned to **7.2.2** (Apache-2.0), not 8.x. | FluentAssertions 8 uses a commercial licence. 7.x has every assertion this project needs. |
| D-5 | 1 | NuGet versions are pinned centrally in `Directory.Packages.props` (§11.1). | One place to review on update. |
| D-6 | 1 | Logging setup (`LogConfigurator`) and the startup sequence (`StorageBootstrapper`) live in `OB2.Storage`, not `OB2.App`. | The exit criteria need log rolling and the full startup tested without WPF (§0). |
| D-7 | 1 | Data layout: `<root>\settings.json`, `<root>\data\ob2.db`, `<root>\data\logs\ob2-YYYYMMDD[_NNN].log`. `<root>` is the exe folder when `portable.flag` exists, otherwise `%APPDATA%\OB2`. | §10.2 says settings and `data/` sit beside the exe; logs are data. |
| D-8 | 1 | `schema_version(version, name, checksum, applied_at)`. Each migration runs in its own `BEGIN IMMEDIATE` transaction with its version row. The runner refuses to start if an applied migration was edited (SHA-256 over line-ending-normalized text) or if the DB has a version this build doesn't know. | A failed migration leaves the DB at the last good version. Editing `001_init.sql` instead of adding `002_*.sql` is caught immediately. A git `autocrlf` difference is not treated as an edit. |
| D-9 | 1 | Migrations are embedded resources, not loose files. | The single-file exe (§12) needs no extra files. |
| D-10 | 1 | SQLite runs with `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, 30 s busy timeout. | WAL stays consistent after a crash. NORMAL can lose the last commit on power loss; the engine reconciles segments against the `.pgpart` file anyway (§11.3). |
| D-11 | 1 | Default user agent is a current Chrome UA string. | Some servers refuse unknown agents; captured downloads send the browser's UA anyway. User-editable (FR-30). |
| D-12 | 1 | Per-category save folders live only in `categories.save_folder`. `settings.json` holds the default save folder. | Avoids two sources of truth for FR-18/FR-29. |
| D-13 | 1 | `defaultSaveFolder` is `null` until the first-run wizard (Phase 5) or the user sets it. | Lets Phase 5 detect first run without a separate flag. |
| D-14 | 1 | Settings loading is forgiving: comments and trailing commas allowed, unknown keys ignored, out-of-range values clamped and logged, an unparseable file backed up as `settings.json.corrupt-<UTC timestamp>` and replaced by defaults. | §4 Reliability: one bad record must not stop the app. |
| D-15 | 1 | Atomic writes use a temp file in the target folder, `Flush(true)`, then `File.Move(overwrite: true)` (MoveFileEx replace). | Same-volume rename is atomic on NTFS; flushing first avoids a zero-length file after power loss. |
| D-16 | 1 | UI strings live in `OB2.App/Resources/Strings.xaml` (a WPF ResourceDictionary). | Externalized for translation (NFR Localization) with no code generator. |
| D-17 | 1 | Analyzer rules: warnings are errors; `CA1716` is off (the `OB2.Shared` name is fixed by §7.3); `CA1848` is a suggestion. | Keeps the build strict without fighting the mandated project names. |
| D-18 | 1 | The app manifest declares PerMonitorV2 DPI awareness, `asInvoker`, and long-path awareness. | NFR Accessibility (125%/150%), AC-9 (no admin prompt), deep download folders. |
| D-19 | 2 | Pre-allocation uses `FileStream.SetLength` only. `SetFileValidData` is not attempted. A free-space check runs before a download starts (`DISK_FULL`). | `SetFileValidData` needs `SeManageVolumePrivilege`, which a non-admin portable app never has (§10.3 allows the fallback). The free-space check gives the early failure that pre-allocation was meant to give. |
| D-20 | 2 | The CLI is `ob2.exe get <url> [--out] [--sha256\|--md5] [--name] [--connections] [--data]`, with a `get` verb. Exit codes: 0 ok, 1 failed, 2 checksum mismatch, 3 paused, 64 usage. Re-running the same command resumes. | §15 shows `ob2.exe <url> [...]`, but §8.5 also uses `ob2.exe "https://..."` to hand a URL to the GUI. The verb keeps both meanings apart. `--data` isolates test runs. |
| D-21 | 2 | Every job start probes again. If size, ETag, or (without an ETag) Last-Modified changed, the download restarts from zero. | Mixing bytes from two versions of a file is the worst failure. The fresh probe also refreshes an expired final URL. |
| D-22 | 2 | Checkpoint order: snapshot segment counters → `FlushFileBuffers` → one SQLite transaction. On resume, segment counts are clamped to the file length on disk. | The database can never claim bytes that are not on disk, so a crash at any point resumes correctly (§11.3). |
| D-23 | 2 | Cookies are kept in an in-memory map in the engine, keyed by download id. They are never written to SQLite or logs. "Remember auth" (DPAPI) is not built yet. | §11.1 default behaviour. After an app restart, authenticated downloads resume without cookies; see backlog. |
| D-24 | 2 | One shared `HttpClient`: `SocketsHttpHandler`, no automatic decompression, `Accept-Encoding: identity`, `UseCookies=false`, at most 10 redirects, system proxy, infinite client timeout (per-read idle timeouts instead). | Byte ranges must address the raw entity. Cookies must be exactly the browser's. Long downloads must not hit a whole-request timeout. |
| D-25 | 2 | A segment with unknown size is stored with `range_end = -1` (open-ended). | Keeps the v1 schema; the inclusive end is set once the stream ends. |
| D-27 | 3 | Retries: "5 retries" means 1 attempt + 5 retries per segment. The counter resets when an attempt made progress. A worker shed by the adaptive limit hands its segment back without spending a retry. Backoff is 1 s × 2ⁿ⁻¹, capped at 30 s, ±20 % jitter, `Retry-After` honoured (capped). Transient: network errors, timeouts, 408/425/429/5xx. Permanent: other 4xx, disk errors, path errors. | FR-6. A server that keeps delivering bytes between drops should not fail a long download. AC-3 is exact with one connection (6 drops without progress fail). |
| D-28 | 3 | Multi-segment `.pgpart` files are created **sparse** (FSCTL_SET_SPARSE on a short-lived sync handle), then `SetLength(total)`; the sparse flag is cleared on completion. Single-segment files are ordinary. | Without it, NTFS zero-fills everything up to the furthest segment's first write, which doubles disk I/O on large files (§16.1 "slow I/O on HDD"). |
| D-29 | 3 | Adaptive connections (§16.1): 3 throttling errors (429, 503, or connection failure before any byte) halve that download's connection limit, minimum 1. Workers above the limit finish or hand back their segment. A per-host cap (default 16 across all downloads) bounds the total. | Servers that refuse parallel connections still finish (test: `maxConcurrent=2`). |
| D-30 | 3 | If a server ignores `Range` after advertising it (200 for a ranged request, or a wrong `Content-Range`), the job falls back once to a single connection from byte 0. | FR-4; mixing a full response into a segment would corrupt the file. |
| D-31 | 3 | While any segment is waiting to retry, the download is `retrying`; the first new bytes switch it back to `downloading`. | Flow C ("Waiting for network") needs a visible state. |
| D-32 | 3 | The 1 GiB AC-1 test and the throughput benchmark run only with `OB2_RUN_LARGE=1`. | Keeps the default suite (and CI) under a minute; results are recorded in the phase report. |
| D-33 | 4 | A category with no folder saves to `<default folder>\<category name>` (e.g. `Downloads\Video`). Files that match no category go to the default folder. Migration `002` seeds Documents, Music, Video, Programs, Compressed and the "Main" queue (concurrency 3). | Familiar IDM layout; FR-18/FR-29. |
| D-34 | 4 | Queue semantics: **Download Now** starts immediately, outside any queue limit. **Download Later** marks the item `queued` in its queue. A running queue starts `queued` items in `queue_position` order up to its concurrency. Stopping a queue checkpoints its running items and puts them back to `queued`. A queue "finishes" only if it started at least one download in that run; an empty queue never fires its completion action. | Flow B needs stopped items to resume next run. Shutting a PC down because an empty queue "finished" would be a nasty surprise. |
| D-35 | 4 | The scheduler is edge-triggered and evaluated every 15 s. Entering a window starts the queue; leaving it stops it. An overnight window (stop < start) belongs to its start day. Without a stop time the queue runs until empty. Opening the app inside a window starts the queue. Times are local wall-clock. | FR-16, AC-10; testable with the `IClock` abstraction. |
| D-36 | 4 | Completion actions: Close/Sleep/Shut down wait behind a 30-second cancellable countdown. Shutdown uses `shutdown /s /t 60` (Windows' own warning; `shutdown /a` aborts). Run command uses `cmd /c` with no window. | FR-17; never power off a PC without a chance to cancel. |
| D-37 | 4 | FR-27 notifications use the tray icon's balloon notification (shown as a toast on Windows 10/11), not `Microsoft.Toolkit.Uwp.Notifications`. | The toolkit needs a `net8.0-windows10.0.17763` target and the WinRT projection (~20 MB) for the same visible result. Deviation from §6.2. |
| D-38 | 4 | Tray: `H.NotifyIcon.Wpf` pinned to **2.3.2**. | 2.4.x ships only net10.0 and .NET Framework builds. |
| D-39 | 4 | The Download Complete dialog (§9.3) appears only for downloads that are not part of a running queue (queue runs notify only), unless the user turned it off globally or for that category. | A night queue of 50 files should not leave 50 dialogs open in the morning. |
| D-40 | 4 | The UI pulls engine progress snapshots on a 250 ms timer (NFR 4 Hz). Status changes arrive as engine events marshalled to the dispatcher. | Bounded UI cost regardless of how fast bytes arrive. |
| D-41 | 4 | GUI command line: `ob2.exe [url] [--data <dir>] [--minimized]`. A URL opens the Add dialog (§8.5). Drag-and-drop of links/text onto the window and a clipboard URL also pre-fill it (FR-1). | §8.5, FR-1. |
| D-42 | 4 | Opening a downloaded `.exe .msi .bat .cmd .ps1 .scr .com .vbs .js .jse .wsf .hta .lnk .msix .appx` asks first (default button: No). | §11.1 lists the first five; the rest are equally executable. |
| D-43 | 4 | The per-download speed limit (FR-9 second half) is built: a field in the Add dialog, applied as a second token bucket on that job. | It was a 10-line change once the Add dialog existed. |
| D-26 | 2 | Mark-of-the-Web (`Zone.Identifier`, ZoneId=3, HostUrl/ReferrerUrl without credentials) is written right after the final rename. Failure, for example on FAT32, is ignored. | §11.1. |
| D-44 | 4 | One `InstanceLock` per data folder (`data\ob2.lock`, opened with `FileShare.None` and `DeleteOnClose`). Only the process holding it runs crash recovery. | Concurrent CLI runs on one folder marked each other's live downloads as paused. |
| D-49 | 4 | The app logs a `Memory:` line (managed heap, GC committed, private bytes, working set, GC counts, active downloads) every 5 minutes. `OB2_MEMORY_LOG_SECONDS` shortens the interval. | AC-12 in the field: shows whether growth is managed or native without attaching a profiler. |
| D-45 | 5 | When `portable.flag` exists but the exe folder is not writable (probed with a temporary file), data goes to `%APPDATA%\OB2` and `AppPaths.FellBackFromReadOnly` is set. The probe is injectable for tests. | §12.3. A copy on a read-only share or under Program Files still starts. |
| D-46 | 5 | The first-run wizard appears only while `folders.defaultSaveFolder` is null and the start is not tray-only (`--minimized` / `--from-host`). | A browser capture that launches the app must not block on a window. Downloads use the Downloads folder until the wizard runs. |
| D-47 | 5 | `build/publish.ps1` writes `publish/OB2-portable/` (OB2.exe, portable.flag, README.txt, plus host.exe with `-IncludeHost` and `chrome-extension/` when built), `OB2-portable.zip`, and `SHA256SUMS.txt`. Both exes are single-file, self-contained, win-x64, with native libraries inside. | §12.4; checksums let the owner compare files after an antivirus warning. |
| D-48 | 5 | Every launch logs `Startup: tray ready` / `window shown … ms after process start`. | §16.1 asks for startup to be measured; logging it every time also catches regressions on other PCs. |
| D-56 | 5 | The app exe is published **without** `EnableCompressionInSingleFile` (158 MB exe, 65 MB zip). | A compressed exe unpacks its assemblies into private memory: ~98 MB with 10 downloads against ~36 MB uncompressed, so compression fails AC-12. The zip gives almost the same download size. |
| D-50 | 6 | Two additions to §8.3, with `v` still 1 (no existing field changed): error code `INVALID_MESSAGE` (malformed, oversize, or unknown-type messages) and an app-internal `activate` message. | §8.3 has no code for a broken frame. `activate` lets a second `OB2.exe` show the running window. |
| D-51 | 6 | The extension ID is pinned to `mgmmgplfngnhcencbhpfagnjcnenflpm` through the `key` field in `extension/manifest.json` (public key only; the private key was not kept and isn't needed for unpacked loading). | §8.2: the same ID on every PC, so `allowed_origins` works without editing. A Jest test recomputes the ID from the key. |
| D-52 | 6 | The pipe name `OB2-<16 hex>` is generated on the app's first start and stored as `ipc.pipeName` in `settings.json`. host.exe reads it through `HostLocator`: portable settings first, then `%APPDATA%\OB2`. | §11.1 per-install random suffix, without a second config file. |
| D-53 | 6 | With confirmation on, the app acks `"confirming"` immediately and shows the Add window. With it off, the app adds the download from the browser's hints and acks with the new id; the job probes the server when it starts. | Keeps the 2-second ack budget (§8.3) even when a probe would be slow. If the user cancels the dialog, the browser download is already gone; that is accepted. |
| D-54 | 6 | A second `OB2.exe` for the same data folder forwards `add_download` (source `cli`) or `activate` over the pipe, then exits. | §8.5 single instance; closes the Phase 1 backlog item. |
| D-55 | 6 | The app repairs the Chrome registration on start only when the manifest or the host.exe it points at no longer exists. A registration for another working copy is left alone; Options shows "registered for another copy" and the Register button moves it. | §12.6 (moved folder). Without this, two copies on one PC, or the test suite's temporary copies, would take the registration from each other on every start. |
| D-57 | 6 | `capture_rules_updated` is never sent. The rules travel in every `status` reply. The extension caches them and refreshes on install, on browser start, while the popup is open, and in the background when they are over 10 minutes old. | `sendNativeMessage` is one request, one reply: the app has no channel to push on. A long-lived `connectNative` port would keep host.exe running all the time. |
| D-58 | 6 | Capture order: pause the browser download → send `add_download` → on `ack` cancel and erase it; on anything else (no host, error reply, 20 s timeout) resume it. | §8.4 says cancel only after the ack (fail-open). §7.4 step 3 says cancel first; pausing satisfies both. |
| D-59 | 6 | A captured URL with embedded credentials (`user:pass@host`) always opens the Add window, even with confirmation off. | §11.1: "Reject URLs with embedded credentials unless the user confirms." |
| D-60 | 6 | host.exe uses a 300 ms connect timeout for a running app. After starting OB2 it connects with the remaining 15-second budget, so the request goes the moment the pipe exists. | Measured: a capture that starts OB2 took 4.6 s with the earlier 700 ms timeout and polling (AC-6 allows 5 s); now 1.8–2.0 s, and 3.9 s on the first run of a fresh copy. |
| D-61 | 6 | The extension does not capture incognito downloads, downloads started by any extension (including its own context-menu fallback), non-HTTP URLs, or Shift-clicked links. A listed file type of unknown size is captured. The type comes from Chrome's file name, else the URL path, else the MIME type. Excluded domains match the download host and the referring page, including subdomains. | Incognito cookies must not leave the incognito session. The extension-origin check prevents capture loops. Many download links (`download?id=…`) only reveal their type through the MIME type. |
| D-62 | 6 | Extension toolchain: TypeScript 5.9 (pinned; ts-jest does not support 7.x), esbuild IIFE bundles for Chrome 116+, Jest 30 with jsdom for the content script and popup. `extension/dist` is built by `npm run build` or `publish.ps1 -IncludeHost` and is not committed. | §14.1 Extension row. Built output in git goes stale. |
| D-63 | 1.0 | Target **.NET 10** (`net10.0` / `net10.0-windows`, C# 14) instead of .NET 8. `global.json` requires SDK 10.0.100 or later. Microsoft packages moved to 10.0.12, and H.NotifyIcon.Wpf to 2.4.1 (its .NET 8 limit in D-38 no longer applies). CA1873 is a suggestion, like CA1848. | .NET 8 support ends 2026-11-10; .NET 10 is the current LTS (to 2028-11). All 287 tests pass on .NET 10. The throughput benchmark is equal or faster (unthrottled 355/580 MiB/s against 294/432). The single-file app is 137 MB instead of 158 MB. Deviation from §6.2/§13, approved by the owner. |
| D-64 | 1.0 | Start with Windows (FR-31): a per-user Run value `OB2` = `"<exe>" --minimized` (plus `--data` when the app was started with it). On start the app repairs a value whose exe no longer exists, but leaves one that points at another working copy. Saving Options replaces another copy's value only when the user changed this checkbox. | HKCU needs no admin rights. Same reasoning as D-55: two copies must not take the setting from each other, and saving an unrelated option must not undo another copy's choice. |
| D-65 | 1.0 | Edge support: Register and Unregister also write and remove `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.ob2.host`, pointing at the same manifest. The extension is unchanged apart from wording: Edge loads the same unpacked MV3 build, the `key` gives the same ID, and the origin is `chrome-extension://`. A registration of this copy that is missing a browser is completed on start. | One build covers both Chromium browsers. Completing a partial registration upgrades 0.6 installs without a click, and never takes keys from another copy (D-55). |
| D-66 | 1.0 | Expired download addresses (§16.1): when a segment gets 401, 403, 404 or 410, the job asks the original link again (one shared refresh for all segments, at most 3 per run). If the link gives a new address for the same file (same size, ETag or Last-Modified), segments continue there without spending a retry, and the new address is saved with a `url-refreshed` history event. If it gives the same address, can't be probed, or now serves a different file, the download fails as before, keeping its progress. | Signed CDN links often expire within minutes, which killed long downloads. Checking the file identity before splicing in bytes from the new address is the same rule as D-21. |
| D-67 | 1.0 | "Remember auth" (§11.1): with Options > General > "Remember website sign-ins" on, the cookies of an unfinished download are saved in a new `download_secrets` table (migration 003), encrypted with DPAPI for the current Windows user plus a fixed purpose string. A download started without cookies in memory (after a restart) loads them. They are deleted when the download completes, when it is removed (foreign-key cascade), and all at once when the option is turned off. Turning it on saves the cookies already in memory. A row that can't be decrypted (another user or PC, damaged) is deleted and the download continues without cookies. Off by default. | The PRD asks for opt-in, DPAPI-encrypted persistence. Keeping secrets only for unfinished downloads limits exposure. A portable copy carried to another PC never exposes or reuses them. |
| D-68 | 1.0 | host.exe is published **trimmed and ReadyToRun** (`PublishTrimmed`, `PublishReadyToRun`, invariant globalization, JSON reflection off). All protocol JSON goes through a source-generated `ProtocolJsonContext` (the host manifest through its own snake_case context), and `OB2.Shared` is `IsTrimmable`, so any reflection there fails the build. | Measured A/B, one host process per message as Chrome runs it: untrimmed 70.2 MB, 105–127 ms per message. Trimmed only: 12.4 MB but 250–350 ms, because trimming drops the framework's precompiled code. Trimmed + ReadyToRun: **16.8 MB, 66–99 ms**, and a capture that starts OB2 takes 1.2–1.4 s. The zip shrinks from 88.6 to 65.8 MB. |
| D-69 | 1.0 | Media detection (FR-24) with an IDM-style button over videos. The extension gains the `webRequest` permission (observe only, no blocking) and watches `media` and `xmlhttprequest` responses. A 200/206 reply with a `video/*` or `audio/*` type, or a generic type on an address ending in a media extension, is sent to the frame that loaded it; the whole size comes from `Content-Range` on a 206. Left out: HLS/DASH manifests and segments (`m3u8 mpd ts m4s`, `video/mp2t`, `*/iso.segment`), URLs with `range`/`bytestart`/`byteend` query parameters (one chunk of a file, as YouTube and Facebook use), and files under 1 MB. The button appears over a video of at least 200×100 px while the pointer is on it, and for 4 s when one starts playing. It offers the element's own http(s) file, else the files that frame loaded, newest first (a menu when there are several). A new context-menu item "Download media with OB2" on video/audio elements does the same. Requests use `source: "chrome-media"` (the app treats it as Chrome), the page as referrer, and the page title as the file name when the address has none. Fail-open as for links; nothing from Incognito. The popup can turn the button off. | FR-24 (P2) asks for media detection. OB2's engine downloads single files, so only direct files are offered; segmented streams would download as a useless manifest or fragment. Observing responses is the only way to see the file behind a `blob:` player. The frame keeps its own list, so the service worker stores nothing about browsing (§11.2). The button sits in a closed shadow root, built without `innerHTML`, so page CSS, scripts and Trusted Types don't affect it. |
