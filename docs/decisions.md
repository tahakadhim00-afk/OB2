# Decisions

Choices made where the PRD says *(decide)*, leaves a detail open, or where the build deviates from §13. Newest last.

| # | Phase | Decision | Reason |
|---|-------|----------|--------|
| D-1 | 1 | The project has its own git repo at `OB2/`. | The enclosing folder sits inside an unrelated repo rooted at the user profile. Phase branches and tags must not mix with it. |
| D-2 | 1 | The PRD stays at the repo root as `OB2_PRD.md` rather than `docs/PRD.md` (§7.3). | That is the file the owner works from; a copy would drift. |
| D-3 | 1 | Target `net8.0` / `net8.0-windows` as §6.2 specifies. Built with the .NET 9 SDK (9.0.301); tests run on the .NET 8 runtime. | Follows §13. **Note:** .NET 8 support ends 2026-11-10. Moving to .NET 10 LTS is logged in the backlog for the owner to approve. |
| D-4 | 1 | FluentAssertions is pinned to **7.2.2** (Apache-2.0), not 8.x. | FluentAssertions 8 uses a commercial licence. 7.x has every assertion this project needs. |
| D-5 | 1 | NuGet versions are pinned centrally in `Directory.Packages.props` (§11.1). | One place to review on update. |
| D-6 | 1 | Logging setup (`LogConfigurator`) and the startup sequence (`StorageBootstrapper`) live in `OB2.Storage`, not `OB2.App`. | The exit criteria need log rolling and the full startup tested without WPF (§0). |
| D-7 | 1 | Data layout: `<root>\settings.json`, `<root>\data\ob2.db`, `<root>\data\logs\ob2-YYYYMMDD[_NNN].log`. `<root>` is the exe folder when `portable.flag` exists, otherwise `%APPDATA%\OB2`. | §10.2 says settings and `data/` sit beside the exe; logs are data. |
| D-8 | 1 | `schema_version(version, name, checksum, applied_at)`. Each migration runs in its own `BEGIN IMMEDIATE` transaction with its version row. The runner refuses to start if an applied migration was edited (SHA-256 over line-ending-normalized text) or if the DB has a version this build doesn't know. | A failed migration leaves the DB at the last good version. Editing `001_init.sql` instead of adding `002_*.sql` is caught immediately. A git `autocrlf` difference is not treated as an edit. |
| D-9 | 1 | Migrations are embedded resources, not loose files. | The single-file exe (§12) needs no extra files. |
| D-10 | 1 | SQLite runs with `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, 30 s busy timeout. | WAL stays consistent after a crash. NORMAL can lose the last commit on power loss; the engine reconciles segments against the `.pgpart` file anyway (§11.3). |
| D-11 | 1 | Default user agent is a current Chrome UA string. | Some servers refuse unknown agents; captured downloads send the browser's UA anyway. User-editable (FR-30). |
| D-12 | 1 | Per-category save folders live only in `categories.save_folder`. `settings.json` holds the default save folder. | Avoids two sources of truth for FR-18/FR-29. |
| D-13 | 1 | `defaultSaveFolder` is `null` until the first-run wizard (Phase 5) or the user sets it. | Lets Phase 5 detect first run without a separate flag. |
| D-14 | 1 | Settings loading is forgiving: comments and trailing commas allowed, unknown keys ignored, out-of-range values clamped and logged, an unparseable file backed up as `settings.json.corrupt-<UTC timestamp>` and replaced by defaults. | §4 Reliability: one bad record must not stop the app. |
| D-15 | 1 | Atomic writes use a temp file in the target folder, `Flush(true)`, then `File.Move(overwrite: true)` (MoveFileEx replace). | Same-volume rename is atomic on NTFS; flushing first avoids a zero-length file after power loss. |
| D-16 | 1 | UI strings live in `OB2.App/Resources/Strings.xaml` (a WPF ResourceDictionary). | Externalized for translation (NFR Localization) with no code generator. |
| D-17 | 1 | Analyzer rules: warnings are errors; `CA1716` is off (the `OB2.Shared` name is fixed by §7.3); `CA1848` is a suggestion. | Keeps the build strict without fighting the mandated project names. |
| D-18 | 1 | The app manifest declares PerMonitorV2 DPI awareness, `asInvoker`, and long-path awareness. | NFR Accessibility (125%/150%), AC-9 (no admin prompt), deep download folders. |
| D-19 | 2 | Pre-allocation uses `FileStream.SetLength` only. `SetFileValidData` is not attempted. A free-space check runs before a download starts (`DISK_FULL`). | `SetFileValidData` needs `SeManageVolumePrivilege`, which a non-admin portable app never has (§10.3 allows the fallback). The free-space check gives the early failure that pre-allocation was meant to give. |
| D-20 | 2 | The CLI is `ob2.exe get <url> [--out] [--sha256\|--md5] [--name] [--connections] [--data]`, with a `get` verb. Exit codes: 0 ok, 1 failed, 2 checksum mismatch, 3 paused, 64 usage. Re-running the same command resumes. | §15 shows `ob2.exe <url> [...]`, but §8.5 also uses `ob2.exe "https://..."` to hand a URL to the GUI. The verb keeps both meanings apart. `--data` isolates test runs. |
| D-21 | 2 | Every job start probes again. If size, ETag, or (without an ETag) Last-Modified changed, the download restarts from zero. | Mixing bytes from two versions of a file is the worst failure. The fresh probe also refreshes an expired final URL. |
| D-22 | 2 | Checkpoint order: snapshot segment counters → `FlushFileBuffers` → one SQLite transaction. On resume, segment counts are clamped to the file length on disk. | The database can never claim bytes that are not on disk, so a crash at any point resumes correctly (§11.3). |
| D-23 | 2 | Cookies are kept in an in-memory map in the engine, keyed by download id. They are never written to SQLite or logs. "Remember auth" (DPAPI) is not built yet. | §11.1 default behaviour. After an app restart, authenticated downloads resume without cookies; see backlog. |
| D-24 | 2 | One shared `HttpClient`: `SocketsHttpHandler`, no automatic decompression, `Accept-Encoding: identity`, `UseCookies=false`, at most 10 redirects, system proxy, infinite client timeout (per-read idle timeouts instead). | Byte ranges must address the raw entity. Cookies must be exactly the browser's. Long downloads must not hit a whole-request timeout. |
| D-25 | 2 | A segment with unknown size is stored with `range_end = -1` (open-ended). | Keeps the v1 schema; the inclusive end is set once the stream ends. |
| D-27 | 3 | Retries: "5 retries" means 1 attempt + 5 retries per segment. The counter resets when an attempt made progress. A worker shed by the adaptive limit hands its segment back without spending a retry. Backoff is 1 s × 2ⁿ⁻¹, capped at 30 s, ±20 % jitter, `Retry-After` honoured (capped). Transient: network errors, timeouts, 408/425/429/5xx. Permanent: other 4xx, disk errors, path errors. | FR-6. A server that keeps delivering bytes between drops should not fail a long download. AC-3 is exact with one connection (6 drops without progress fail). |
| D-28 | 3 | Multi-segment `.pgpart` files are created **sparse** (FSCTL_SET_SPARSE on a short-lived sync handle), then `SetLength(total)`; the sparse flag is cleared on completion. Single-segment files are ordinary. | Without it, NTFS zero-fills everything up to the furthest segment's first write, which doubles disk I/O on large files (§16.1 "slow I/O on HDD"). |
| D-29 | 3 | Adaptive connections (§16.1): 3 throttling errors (429, 503, or connection failure before any byte) halve that download's connection limit, minimum 1. Workers above the limit finish or hand back their segment. A per-host cap (default 16 across all downloads) bounds the total. | Servers that refuse parallel connections still finish (test: `maxConcurrent=2`). |
| D-30 | 3 | If a server ignores `Range` after advertising it (200 for a ranged request, or a wrong `Content-Range`), the job falls back once to a single connection from byte 0. | FR-4; mixing a full response into a segment would corrupt the file. |
| D-31 | 3 | While any segment is waiting to retry, the download is `retrying`; the first new bytes switch it back to `downloading`. | Flow C ("Waiting for network") needs a visible state. |
| D-32 | 3 | The 1 GiB AC-1 test and the throughput benchmark run only with `OB2_RUN_LARGE=1`. | Keeps the default suite (and CI) under a minute; results are recorded in the phase report. |
| D-26 | 2 | Mark-of-the-Web (`Zone.Identifier`, ZoneId=3, HostUrl/ReferrerUrl without credentials) is written right after the final rename. Failure, for example on FAT32, is ignored. | §11.1. |
