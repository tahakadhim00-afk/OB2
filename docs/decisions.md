| D-20 | 2 | The CLI is `ob2.exe get <url> [--out] [--sha256\|--md5] [--name] [--connections] [--data]`, with a `get` verb. Exit codes: 0 ok, 1 failed, 2 checksum mismatch, 3 paused, 64 usage. | D-22 | 2 | Checkpoint order: snapshot segment counters → `FlushFileBuffers` → one SQLite transaction. On resume, segment counts are clamped to the file length on disk. | The database can never claim bytes that are not on disk, so a crash at any point resumes correctly (§11.3). |
| D-23 | 2 | Cookies are kept in an in-memory map in the engine, keyed by download id. They are never written to SQLite or logs. "Remember auth" (DPAPI) is not built yet. | §11.1 default behaviour. After an app restart, authenticated downloads resume without cookies; see backlog. |
| D-24 | 2 | One shared `HttpClient`: `SocketsHttpHandler`, no automatic decompression, `Accept-Encoding: identity`, `UseCookies=false`, at most 10 redirects, system proxy, infinite client timeout (per-read idle timeouts instead). | Byte ranges must address the raw entity. | D-25 | 2 | A segment with unknown size is stored with `range_end = -1` (open-ended). | Keeps the v1 schema; the inclusive end is set once the stream ends. |
| D-27 | 3 | Retries: "5 retries" means 1 attempt + 5 retries per segment. The counter resets when an attempt made progress. A worker shed by the adaptive limit hands its segment back without spending a retry. Backoff is 1 s × 2ⁿ⁻¹, capped at 30 s, ±20 % jitter, `Retry-After` honoured (capped). Transient: network errors, timeouts, 408/425/429/5xx. Permanent: other 4xx, disk errors, path errors. | FR-6. A server that keeps delivering bytes between drops should not fail a long download. AC-3 is exact with one connection (6 drops without progress fail). |
| D-28 | 3 | Multi-segment `.pgpart` files are created **sparse** (FSCTL_SET_SPARSE on a short-lived sync handle), then `SetLength(total)`; the sparse flag is cleared on completion. Single-segment files are ordinary. | Without it, NTFS zero-fills everything up to the furthest segment's first write, which doubles disk I/O on large files (§16.1 "slow I/O on HDD"). |
| D-29 | 3 | Adaptive connections (§16.1): 3 throttling errors (429, 503, or connection failure before any byte) halve that download's connection limit, minimum 1.
